# Prompt 4 Cross-Model Handoff: Protocol

**Preregistered 2026-11-27, before any harness run. Status: scripted
run complete (see Results); real two-model run PENDING (credentials).**

## Question

Can an agent B, a different model from agent A with no conversation
history, continue agent A's work from WORLD alone, and how much of
the work state survives compared with a plain summary and a prose
journal (transcript)? Prompt 4 in
`~/workspace/goals/world-90-day-autonomous-engineering-mission/hidden_files/PROMPT_SEQUENCE_2026-11-24.md`.

## Design as preregistered

- One fixed scenario (section "Scenario"), built by a scripted
  Agent A through the shipped `World` code path: a spend update, one
  invariant rejection, two handoff saves (v1, then v2 revising the
  primary decision). Final committed version is 4.
- Three conditions, all derived from the same v2 state (information
  parity: the summary and the journal carry the same facts as the
  packet, in prose; what differs is structure):
  - A = WORLD continuation packet (JSON, `world.continuation_packet`,
    the shipped interface).
  - B = plain summary, generated by a fixed lossy template: objective,
    accepted decision texts, "Assumed: ..." lines, next actions. No
    ids, no confidence, no supersession, no tasks, no evidence
    sources, no rejection, no version.
  - C = prose journal (transcript analogue): dated prose entries
    covering the same facts, no ids, no field structure.
- One scripted Agent B per condition, run as a fresh subprocess
  (`handoff_agent_b.py`) that reads ONLY the bundle file. It never opens the
  world file and never imports `world`. It answers a fixed 10-item
  questionnaire and names the task it would do next. The reader is
  rule-based (fixed regexes and section rules); it measures what the
  representation makes extractable by fixed rules, NOT what a model
  would do. That limit is the whole point of the scripted run and
  the reason the real-model step below is a separate, pending step.
- No significance tests. n = 1 scenario, deterministic. The numbers
  are a measurement of the instrument, not a claim about models.

## Metrics (exact scoring rules, implemented in handoff_harness.py)

Questionnaire items score 1 (full), 0.5 (partial), or 0 (miss).
Continuation success is the mean of the 10 items.

1. Objective: exact normalized match.
2. Authoritative decisions: full if D2 and D3 are listed as
   accepted with correct ids and D1 is not listed as accepted;
   partial if both texts match but ids or status are missing, or
   one of the two matches; miss if D1 is listed as accepted or
   fewer than one matches.
3. Supersession: full if D1 is named superseded with D3 as
   successor; partial if D1 is named superseded with no successor;
   miss otherwise.
4. Assumptions: full if A1 (medium, active) and A2 (low,
   invalidated) match with confidence, status, and ids; partial if
   both texts match but metadata is missing, or one is fully
   correct; miss otherwise.
5. Evidence: full if E1 and E2 claims match with sources; partial
   if both claims match without sources, or one is full; miss
   otherwise.
6. Remaining tasks: full if t-draft (in_progress) and t-interview
   (blocked) match with statuses and t-collect is absent; partial
   if at least one matches and t-collect is absent; miss if
   t-collect is listed as remaining or none match.
7. Completed work: full if t-collect (done) and D3 (accepted) are
   both listed; partial if one is; miss if neither is.
8. Next action: full on exact normalized match; partial on
   normalized containment either way; miss otherwise.
9. Known errors: full if all three are present (blocked
   t-interview, invalidated A2, rejected over-cap attempt); partial
   if at least one is; miss if none is.
10. State version: full on exact match (4); miss otherwise.

Derived counts:

- Lost decisions: authoritative decisions (D2, D3) missing or
  misstated, plus 1 if D1 is listed as authoritative.
- Lost evidence: E1/E2 claims missing.
- Duplicate work: 1 if B's next task choice is t-collect (done) or
  B lists t-collect as remaining; else 0.
- Wrong assumptions: assumptions stated with wrong confidence or
  status, or stated as fact rather than assumption. (D1 treated as
  authoritative counts under lost decisions, not here.)
- Recovery time: wall seconds of the agent_b subprocess.
- Bundle size: word count of the bundle file. This is a word count,
  labeled as words, NOT a token count.
- Human intervention: 0 by construction for scripted agents;
  recorded as not applicable to the scripted run.

## What the scripted run can and cannot show

It CAN show: which fields each representation carries in a form a
fixed reader can extract; the word cost of each representation; that
the packet round-trips through a fresh process with no world access.
It CANNOT show: what any real model would recover, whether a model
would hallucinate or contradict the state, or how much a human
would need to intervene. Those need the real-model step.

## Negative findings

Recorded here, in plain words, when the run shows them (for
example: a condition that ties the packet, a metric where the
packet loses, a parser failure). The scripted run is expected to
show the packet ahead on structured items and behind on word cost;
if it does not, that is the finding, not a reason to re-run until
it does.

Measured 2026-11-27 (scripted run):

1. **The journal ties the packet on 3 of 10 items.** Evidence,
   remaining tasks, and known errors all score 1.0 under the
   journal: its prose markers ("Evidence:", "In progress:",
   "Blocked:", "refused") carry those facts in extractable form.
   The packet's edge is concentrated in supersession links,
   assumption metadata (confidence, status), and version pinning.
   A journal that quotes exact strings is a strong baseline; the
   packet wins where prose has no field for the fact.
2. **The packet is the most verbose bundle by far: 451 words
   against 56 (summary) and 164 (journal).** That is 8.0x the
   summary and 2.7x the journal for a 1.00 against 0.30 and 0.65
   continuation score. Same shape as Experiment #003 (bundles cost
   2.7x to 3.3x the words); the projected packet
   (`continuation_packet(..., projected=True)`) is the untested
   mitigation and should be measured next, not assumed cheaper.
3. **Duplicate work and wrong assumptions are 0 in all three
   conditions.** The fixed readers never duplicate a done task and
   never contradict the state; they lose items instead of getting
   them wrong. Those two metrics only become informative with a
   real model reader, which is the pending step. They are recorded
   as 0 with that limit, not as proof that models would not
   duplicate or contradict.
4. **Recovery time does not distinguish the conditions.**
   Subprocess wall time is 0.052 s (packet), 0.057 s (summary),
   0.110 s (journal): the journal reader is slowest because it
   parses the most lines, but all three are process-startup
   dominated. Recovery time will only matter with a real model
   reader, where bundle size drives tokens and latency.
